# Reading and repeating the historical fresh-session traces

The [index](index.json) lists the successful baseline replay and all candidate qualification
invocations. Each directory contains prompt.txt, response.md, changes.patch and record.json.
The record identifies changed files, exit, original and published hashes, complete before/after
installation file identities, and the selected business documents for that step. The 25 candidate
sessions include a clarification pause and a retained scope-blocked attempt/retry; they are not
25 unconditional functional passes. Earlier launcher-only failures remain private and were never
counted as successful baseline sessions.

To inspect a state, start a disposable checkout at the Book Library base in the parent README.
Overlay a step's before/docs or after/docs there. Omitted starter vision and architecture stay
at their original base. Never copy these draft specifications into a production project.
The linter from the pinned release/main/candidate can then inspect that state's docs directory.
Keep original diagnostics and other prerequisites visible. A legitimate owner question or delivered
review is progress; do not force a predetermined command or treat every unchanged file as failure.

For a new model replay, use a separate fresh checkout starting from the pinned starter and restore
the five-package tessl.json setup before authoring. Record the host, CLI, resolved skill-file hashes
and generated setup. Compare against the saved before/file-identities.json inventories; version
labels alone do not prove the same installation. For the candidate trial, the complete core source
at the published fix was overlaid into the installed core and both Codex/agent discovery copies;
the basic skill bodies were unchanged. Record this as a source overlay, not a released installation.
No dependency installation or model replay was performed during this publication stage.

Run one recorded command per fresh session, carry only actual owner answers into its continuation,
and keep the expectation/assessment outside evaluated prompts. Run next again after each delivered
recommendation. Bound the trial to two additional recommendation cycles and stop early when completed
work returns to the same unresolved cause without meaningful progress. Keep tool errors, owner
decisions and newly discovered prerequisites separate. Save your own raw outputs, snapshots and diffs.
The original clean replay produced different requirements/use-case counts naturally; that is retained.

The definitive checks are recovery from the frozen loop, clean progression after the first written
specification, missing-link repair, clearing the repaired warning, and retaining diagram work for a
genuinely unmapped requirement. Preserve all remaining missing specifications and lint warnings.
The [assessment](assessment.json) records observed results, not instructions to evaluated sessions.

Published text uses canonical LF line endings; original raw hashes remain recorded separately.
Paths in the published prompt/response derivatives may contain {CONSUMER}, {LOCAL_REPLAY}, {HOME},
{PRIVATE_PREPARATION} or {PRIVATE_TRACKER}. Substitute only your own disposable paths; their original
spelling is not required for reproduction. Raw event streams and private tracker contents are excluded.
Original archive hashes are provenance of retained private records, not public download links.
